7. GitHub Integration

Why Connect GitHub?

CourseFoundry autosaves your work continuously to its own database. GitHub integration adds an additional layer: versioned snapshots. Every time you commit, a complete copy of your course files is pushed to a private GitHub repository.

This gives you: - Version history — go back to any previous state - Disaster recovery — restore your course if you accidentally delete content - Portability — your content lives in a standard Git repo you own - GitHub Pages publishing — automatically render and publish your course as a website (see below) - Collaboration potential — others can clone, fork, or contribute via GitHub

Connecting Your Account

  1. Go to Settings (link in the sidebar or top nav)
  2. Scroll to the GitHub section
  3. Click Connect GitHub
  4. You’ll be redirected to GitHub to authorise CourseFoundry
  5. After authorising, you’re returned to Settings with your GitHub username shown

You only need to connect once. The connection persists across sessions.

Committing a Snapshot

  1. Open a course in the editor
  2. Click the Git tab in the right panel
  3. Write a commit message describing what you changed (e.g. “Add module 2 lessons” or “Fix assessment answers”)
  4. Click Commit to GitHub

On the first commit for a course, CourseFoundry automatically creates a private GitHub repository named coursefoundry-[course-slug] in your GitHub account. Subsequent commits push to the same repository.

A success message shows the commit SHA and a link to view it on GitHub.

The most recent commit SHA (first 7 characters) is also shown at the bottom of the editor’s left sidebar as a clickable link to the commit on GitHub — so you can always see at a glance what version the course is at.

Viewing Commit History

In the Git tab, the History section shows the last 20 commits for the current course. Each entry shows: - Commit message - Date and time - Author - Short commit SHA

Restoring from a Previous Commit

  1. In the Git tab, find the commit you want to restore in the history list
  2. Click Restore next to that commit
  3. A preview of the files from that commit is shown
  4. Confirm to overwrite the current course files with the restored version

Warning: Restoring a commit overwrites your current course files. This action cannot be undone within CourseFoundry. If you have unsaved changes you want to keep, commit them first before restoring an older version.

What Is and Isn’t Synced

Synced to GitHub: - All course files (_quarto.yml, .qmd files, etc.) - File content and structure as it exists at the time of commit

Not synced: - Course metadata (title, description, status, slug) — stored in CourseFoundry only - AI credits or usage history - Publish status

GitHub Pages — Auto-publish Your Course as a Website

Once your course has been committed to GitHub at least once, you can enable GitHub Pages to automatically publish your course as a rendered Quarto website.

How it works:

  1. In the editor, open the Git tab
  2. Scroll to the GitHub Pages section
  3. Click Enable GitHub Pages

CourseFoundry will: - Create a separate public GitHub repository (coursefoundry-[slug]-pages) in your account - Set up an Ed25519 deploy key so the workflow can push rendered output - Add a PAGES_DEPLOY_KEY Actions secret to your source repo - Commit a GitHub Actions workflow (.github/workflows/publish.yml) to your source repo

From that moment on, every commit to your source repo triggers the workflow: 1. Quarto renders your course files (quarto render) → produces _output/ HTML output 2. The rendered site is pushed to the gh-pages branch of the output repo 3. GitHub Pages serves it at https://[your-github-username].github.io/coursefoundry-[slug]-pages/

The Pages URL is shown in the Git panel with a Live badge. The site updates automatically — no manual steps needed after enabling.

The rendered site uses a docked collapsible sidebar for navigation, with reader mode and full-text search built in. Only folders and files that are visible (not hidden via the Eye toggle) appear in the sidebar — hidden weeks or modules are excluded from the published output automatically.

To disable: Click Disable Pages in the Git tab. This removes the workflow file and deploy key. The output repository is left intact in your GitHub account (you can delete it manually if you wish).

Note: GitHub Pages requires your Quarto source files to produce valid output. If quarto render fails (e.g. missing _quarto.yml, broken syntax), the Actions run will fail and the site will not update. Check the Actions tab on your source repo to diagnose failures.

Disconnecting GitHub

  1. Go to Settings → GitHub
  2. Click Disconnect

Disconnecting removes the OAuth connection from CourseFoundry. Your GitHub repositories and their contents are not affected — they remain in your GitHub account.

To reconnect in future, repeat the connection steps.

Current Limitations

  • Branch per cohort or version
  • Pull request-based content review workflow
  • Multi-author collaboration via forks
